# Response to the code reviews

Each finding was checked against the code. For a real defect, I wrote a test,
saw it fail on the unchanged code, made the fix, and saw it pass. The whole
suite passes (`npm test`: 21 files, 138 tests). Because the Caddyfile changed,
the local Docker Compose run (`notes-dev`, `NOTES_HOST=localhost`) was repeated.
It checked Caddy's real log lines, the image headers, `data copy`, and the
browser flows over HTTPS, and was then removed.

Summary: 23 fixed, 3 not a defect, 1 not fixed.

| # | Finding | Raised by | Verdict | Evidence |
|---|---|---|---|---|
| 1 | Concurrent sign-in attempts get past the failed-sign-in limits | b01, b02, b04, b05, b06 | fixed | `signin-limit.test.ts` "counts attempts that are still in flight": 30 parallel guesses gave 30 × 401 before the fix; now at most 5, because attempts are reserved before the Argon2 check. |
| 2 | A sign-in being verified when the password changes (or the user is disabled) still gets a session | b02, b04, b05, b06 | fixed | `sessions.test.ts` "a sign-in that is verifying when the password changes does not get a session" (and the "…user is disabled…" twin): the session is now created in one transaction only if the hash and enabled flag are unchanged. |
| 3 | IPv6 clients can rotate addresses within a /64 | b02 | not a defect | The Compose network is IPv4-only (no `enable_ipv6`), so Caddy never sees an IPv6 client address and the app never gets an IPv6 rate-limit key. The hostname is an A record. If an AAAA record were ever added, IPv6 visitors would reach Caddy through Docker's proxy and share one address. |
| 4 | `synchronous = NORMAL` can lose confirmed saves on power loss | b03 | fixed | `db.test.ts` "uses WAL, a 5 s busy timeout, foreign keys, and syncs every commit": now `synchronous = FULL`. |
| 5 | A missing image file makes its note unsaveable | b03 | not a defect | SPEC 6.5 requires removing rows that have no file at start. SPEC 6.2 requires every image a body references to exist. The save gets a 400 with "refers to an image that does not exist" and saves again once the broken image is removed. |
| 6 | Two starting processes can overwrite the pre-upgrade snapshot with a migrated database | b03, b05, b09, b16 | fixed | `db.test.ts` "a process that finds another one mid-migration leaves that one's snapshot alone": the version check, the snapshot (taken by a second read-only connection) and the migration now all happen under one write lock. |
| 7 | Year-long private image caching lets another user of the same browser see images | b04 | fixed | `images.test.ts` "a cached image must be revalidated (with the session) before reuse…": the image is now sent with `private, no-cache` and an ETag. The owner gets 304; anyone else gets 404, never 304. |
| 8 | Offline sign-out shows the sign-in page but leaves the session alive | b04 | fixed | `web/signout.test.ts` "when the server cannot be reached, stays signed in, keeps the drafts and says so": only a confirmed DELETE (or a 401) counts as signed out. |
| 9 | Typing before choosing Restore/Discard overwrites and then deletes the stored draft | b04, b11 | fixed | `web/editor.test.tsx` "nothing can be typed until Restore or Discard is chosen…": the editor and title are read-only while the offer is open. |
| 10 | `data copy` can silently omit (or crash on) images deleted during the copy, and keep their rows | b04, b05, b06, b09, b13, b15, b16 | fixed | `images.test.ts` "data copy holds the write lock while it copies…" and "data copy fails, and leaves no partial directory, if an image file is missing": the write lock is held while the database is copied and the image files are hard-linked (they never change), so a missing file now fails the copy. |
| 11 | Caddy logs more than method, path, status and duration | b05 | fixed | `deploy.test.ts` "keeps only method, path, status and duration of each request". In the Docker run a real line is `{"request":{"method":"GET","uri":"/api/images/…"},"duration":…,"status":200}` plus the log line's own level, time and message; a custom secret header and the query string do not appear. |
| 12 | A small Markdown table pads out to millions of cells (memory blow-up) | b06 | fixed | `markdown.test.ts` "rejects a small table that would pad out…": 20 KB of Markdown took 5.5 s and 2.9 GB before; now tables are checked against a cell budget before they are built. |
| 13 | One tab's confirmed save deletes another tab's draft for the same note | b06 | fixed | `saver.test.ts` "one tab's confirmed save does not delete a draft another tab wrote…": drafts now record the editor that wrote them, and a save clears only its own. |
| 14 | Hierarchy or Inbox corruption makes folder reads crash | b09 | not a defect | `parent_id` is a foreign key with `ON DELETE CASCADE` and foreign keys are on, so a parent cannot be missing. The Inbox is created in the same transaction as its user and cannot be deleted or moved. Only a hand-edited database could produce the state. |
| 15 | A save that finishes after sign-out recreates a discarded draft | b10 | fixed | `saver.test.ts` "a save that finishes after sign-out…writes no draft and sends nothing more": a disposed saver ignores late answers, and sign-out disposes it before removing drafts. |
| 16 | After a 409 `in_trash`, the open editor never saves again, even once the note is restored | b10 | fixed | `saver.test.ts` "after a save is refused because the note is in Trash, the next edit tries again". |
| 17 | Image uploads are not waited for on switch, are dropped silently after close, and insert at a stale drop position | b10 | fixed | `web/uploads.test.tsx` (three tests): the drop position is remapped through edits, a late upload is reported, and switching notes waits (up to 3 s) for running uploads. |
| 18 | Trash ignores a failed last save; Delete permanently silently destroys the local draft | b10 | fixed | `web/editor.test.tsx` "a note whose last changes could not be saved is not moved to Trash" and "Delete permanently mentions changes kept only on this device, and removes them". |
| 19 | The draft offer goes stale and Restore applies an outdated snapshot | b10, b12 | fixed | `web/editor.test.tsx` "Restore uses the draft as it is stored now…" and "a draft that was removed elsewhere is not restored". With #9, no edit can happen while the offer is open. |
| 20 | Unfiled search is filtered after the 50-result limit | b10, b11 | fixed | `search.test.ts` "can be narrowed to unfiled notes on the server, before the 50-result limit": the server now narrows with `unfiled: true`. |
| 21 | Attribute names inherited from `Object.prototype` give a 500 instead of 400 | b11 | fixed | `conflict.test.ts` "rejects invalid bodies with 400 and changes nothing" (now including `valueOf`, `hasOwnProperty`, `constructor`, `toString`, `__proto__`) uses `Object.hasOwn` lookups. |
| 22 | A revoked agent's name cannot be reused, though the README says "add a new one" | b11 | fixed | `cli.test.ts` "agent add prints a working token once…": the README now says to use another name, and the error explains that the revoked agent keeps its name in `agent list`. Freeing the name would need a table rebuild and would lose its history. |
| 23 | Autosave confirmation calls the first render's `onMeta` (stale search state) | b12 | fixed | `web/editor.test.tsx` "a confirmed save reports to the current onMeta, not the one from the first render". |
| 24 | The four agent clients were never checked by hand (SPEC 8.4) | b14, b16 | not fixed | By instruction: the builder must not test or configure the four clients. The lead arranges verification, and the README marks each entry "not yet verified". |
| 25 | Image decoding has no concurrency bound (memory exhaustion) | b15 | fixed | `images.test.ts` "decodes one image at a time, however many uploads arrive together". The total frame size of animations is not capped, because SPEC 6.5 accepts any decodable image up to 10 MB and 10,000 px per side. |
| 26 | An unlink failure turns a committed delete into a 500 and stops clean-up | b15 | fixed | `images.test.ts` "a file that cannot be unlinked does not turn a committed delete into an error": the row is deleted and the stranded file is removed by the start-up reconciliation. |
| 27 | The "keep mine" test compared a body with itself | b16 | fixed | `conflict.test.ts` "\"keep mine\" saves again with the version from the 409 and wins" now asserts the body equals `doc(p('mine'))`; it passed, so "keep mine" was in fact saving the right body. |
